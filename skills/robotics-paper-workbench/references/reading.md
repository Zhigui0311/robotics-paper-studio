# 精读协议：把论文变成能复述和实现的技术路线

按论文类型选择相关项目。综述论文应分析分类体系、覆盖范围和研究脉络；数据集论文应重点记录采集/标注/许可/划分。不要假设每篇都有神经网络或训练阶段。

## 核心框架

先写一段“由于现有方法在什么条件下遇到什么问题，作者引入什么机制，在哪些条件下获得什么证据”。分别回答：

- 问题：机器人要完成什么，约束和优化目标是什么，原方法的具体瓶颈在哪里？
- 技术主张：真正新增的模块/目标函数/表示/数据策略是什么？哪些是沿用组件？
- 信息流：输入的传感器与状态 → 表示或估计 → 决策/规划/控制 → 动作接口 → 反馈。标出模块边界、频率和时间尺度，缺失则标未报告。
- 训练流：数据来源、监督目标/损失/奖励、优化、预训练与微调、数据划分。
- 部署流：每个时间步做什么，历史窗口、推理延迟、动作块长度、重规划频率和低层控制器怎样衔接。

把结构图与论文的图号对应，不能把自己的概括冒充作者原图。文字解释比无来源的复杂流程图更重要。

## 机器人学习与具身智能

- embodiment：单/双臂、灵巧手、移动操作、人形/足式；真实自由度、执行器和传感器。
- observation：RGB、深度、点云、触觉、力/力矩、本体感知、语言；是否使用只在仿真或训练可得的 privileged state。
- action：关节位置/速度/力矩，EEF 位置/位姿/增量，夹爪；坐标系、单位、旋转表示、绝对/相对控制；由谁做 IK。
- 数据：示教次数与时长、成功/失败样本、遥操作、合成数据、跨本体数据、训练测试泄漏风险。
- 模型：编码器、策略头、生成模型、VLA、世界模型；历史长度、action chunk、训练目标与部署采样成本。
- 泛化：新物体、新场景、新任务、组合、跨本体，分别有什么实验证据？
- 闭环：观测更新、执行窗口、误差反馈、恢复策略；视频演示不能替代系统评测。

## 运动规划与控制

- 明确系统状态、动力学、控制输入、目标/代价函数与硬约束。
- 规划层与控制层是否分开；MPC、轨迹优化、采样规划、WBC、阻抗/导纳、学习控制各承担什么。
- 接触建模、摩擦锥、碰撞与关节/力矩约束；混合系统的模式切换如何处理。
- 求解器、近似、初值、求解频率、预测时域、计算硬件和最坏/平均延迟是否披露。
- 稳定性、递归可行性、安全性等数学结论的假设是什么；不能从经验成功率推导理论保证。
- 仿真到现实的模型误差、延迟、噪声、外部扰动与参数识别如何处理。

## 公式与实验

挑决定方法的公式解释：变量与维度/单位 → 物理或统计意义 → 优化对象 → 约束/假设 → 怎样进入算法。没有必要逐式翻译。

每条关键实验结果记录“任务、硬件/模拟器、数据量、协议、指标单位/方向、数值、重复次数/误差（若有）、基线、表/图定位”。分清百分比与百分点；同一论文不同任务的平均值不可随意重算。

消融用于支持因果贡献，但要检查是否控制数据/算力/模型容量。失败模式区分作者报告、实验可见与你提出的假设。没有运行代码时只给复现条件和风险，不写“已复现”。

## 证据表达

- `[论文]`：正文、附录明确陈述，附 §/Eq./Fig./Table 定位。
- `[代码]`：已查阅仓库文件与提交/版本，说明与论文是否对应。
- `[推断]`：你的机制解释或迁移判断，说明依据和不确定性。
- `[未验证]`：缺原文、缺实验协议或来源冲突，列出下一步所需材料。

同一条结果保留同一版本的来源，会议版与预印本数字不混用。关键术语第一次出现用中文、英文和任务中的作用说明；如 EEF、PnP 等有歧义，按原文定义解释。
